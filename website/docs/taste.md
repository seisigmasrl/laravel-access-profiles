## Round 2 — look and feel
- **Light / dark** — `confirmed`: both; follow the visitor's system.
- **Type feel** — `assumed`: modern sans for text and headings + a technical mono for code and commands. Two families max (website-kit rule). No serif.
- **Density** — `assumed`: lots of air in the hero and section breaks; dense, scannable facts inside the comparison table and FAQ. Max text width ~70 characters.
- **Images** — `assumed`: code blocks + simple diagrams only (tenant → scopes → assignment; deny-wins decision flow). Inline SVG, theme-aware. No stock photos, no illustrations of people, no mascot.

## Round 3 — limits
- **Brand items that must stay** — `assumed`: none exist. No logo yet → **wordmark** "laravel-access-profiles" (or "Access Profiles") in the text family. (WEB.Q6 open; default wordmark.)
- **Must never appear** — `confirmed`: words from any one host app's domain (list in the private plan). `assumed`: stock photos, hype words (see PRODUCT.md "Voice"), invented stats or testimonials, the Laravel logo used as our logo (trademark).
- **Stand apart from** — `assumed`: the large Laravel-ecosystem landing pages (Filament, Livewire) use mascots, stats and sponsor walls. We have none of that yet and should not fake it. Stand apart by honesty: a fair comparison and a "when not to use" section.

## Colour direction (`assumed`, for phase 4 to test)
- One calm accent (a cool blue-green or slate-blue), one "deny" colour used only for deny/negative states, neutrals for the rest.
- Do not use Laravel red as the main accent: it would read as an official Laravel product.
